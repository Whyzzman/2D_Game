# Звук — керівництво

Зафіксовано 2026-09-22 (PHASE 22). Супутній документ до `COMBAT_FEEDBACK.md`.

---

## 1. Головне правило

**Звук служить розумінню бою.** Порядок пріоритетів:

1. небезпечні атаки ворогів;
2. удар / блок / парирування по гравцю;
3. власні атаки;
4. репліки боса;
5. магія й стани;
6. рух;
7. оточення;
8. декоративне.

Геймплейна репліка **завжди** важливіша за атмосферу. Коли голоси
закінчуються, першим замовкає скрип каменю, а не телеграф.

## 2. Архітектура

```
подія геймплею → CombatAudioBinder → AudioManager → голос із пулу
```

**Жоден геймплейний скрипт не грає звук.** Бій, вороги й бос піднімають рівно ті
самі події, що й раніше; `CombatAudioBinder` слухає й просить менеджер. Видаліть
біндер — гра працюватиме, просто мовчки.

Більшість бою приходить через `CombatFeedbackService.Played` — ту саму єдину
точку, яку зробив PHASE 20. Завдяки цьому звук і ефекти **не можуть розійтися**:
заблокований удар звучить як блок в обох, а удар по невразливості мовчить в обох.

| Файл | Роль |
| --- | --- |
| `Runtime/Audio/AudioId.cs` | 88 звуків і 5 шин |
| `Runtime/Audio/AudioEvent.cs` | один звук як дані |
| `Runtime/Audio/AudioLibrary.cs` | покажчик усіх звуків |
| `Runtime/Audio/AudioManager.cs` | голоси, пул, ліміти, пріоритет, дакінг |
| `Runtime/Audio/CombatAudioBinder.cs` | події геймплею → звуки |
| `Runtime/Audio/AmbienceController.cs` | кімната |
| `Runtime/Audio/MusicDirector.cs` | стан музики |
| `Editor/PlaceholderAudioArt.cs` | синтез тимчасових кліпів |

## 3. Шини

| Шина | Що на ній | Регулятор |
| --- | --- | --- |
| Master | усе | «Загальна гучність» |
| Music | музика | «Музика» |
| Sfx | бій, рух, магія | «Ефекти» |
| Ui | меню | немає, фіксовано 0.9 |
| Ambience | кімната | немає, фіксовано 0.75 |

Інтерфейс і кімната **навмисно без окремих повзунків**: екран налаштувань
лишається коротким, а головне — приглушити бій не повинно заразом спорожнити
світ, що й зробив би один спільний повзунок. Це перевіряє тест
`SilencingCombatLeavesTheRoomAudible`.

Налаштування зберігаються окремо від прогресу (`GameSettings`, PHASE 21).

## 4. AudioEvent

| Поле | Навіщо |
| --- | --- |
| `_clips` | варіанти |
| `_volume`, `_volumeJitter`, `_pitchJitter` | рівень і природна варіація |
| `_spatialBlend`, `_maxDistance` | скільки в світі, скільки в голові |
| `_maxVoices` | скільки таких звучить одночасно |
| `_minimumInterval` | мінімальний проміжок |
| `_priority` | хто виживає, коли голоси скінчилися |
| `_loop` | тільки для кімнати |

## 5. Варіація

Крок висоти ±4.5 %, гучності ±6 % — рівно стільки, щоб повтор не читався як
той самий файл, і не настільки, щоб гра звучала іграшково.

**Той самий варіант ніколи не грає двічі поспіль**, коли варіантів більше
одного: саме це робить бібліотеку схожою на бібліотеку. Тримає тест
`VariationPicksDifferentClipsRatherThanTheSameOneRepeatedly`.

Кроків: підлога 6, удари 4, більшість бою 3.

## 6. Ліміти й пріоритет

Ліміт голосів — головний захист від стіни шуму. Три зомбі не звучать утричі
голосніше, бо `ZombieStep` має 3 голоси, а не дев'ять.

**Пріоритет (згори вниз):**

| Пріоритет | Що |
| --- | --- |
| 120 | **телеграф ривка Стража** |
| 115 | зміна фази, смерть боса |
| 110 | стрибок-удар |
| 95 | парирування, злам блоку, пробудження |
| 85–90 | важкі атаки боса, смерть гравця |
| 60–80 | удари, блок, магія, Тінь |
| 40–55 | стани, тривога, інтерфейс |
| 12–35 | кроки, підбирання |
| 5–8 | **кімната** |

Телеграф ривка стоїть вище за **все інше в грі** — гравець, який його не почув,
з'їдає ривок. Це перевіряє тест `TheChargeTelegraphOutranksEverythingElse`.

Коли голоси скінчилися, менеджер забирає найтихіший **не-луп** із нижчим
пріоритетом. Якщо все важливіше — новий звук просто не грає.

## 7. Простір

Гра збоку, тож просторовість — натяк, а не реалізм. `spatialBlend` здебільшого
0.55: ворог ліворуч трохи ліворуч, не в лівому вусі.

**Нуль** у того, що відбувається **з гравцем, а не поруч із ним**: смерть, рівень,
вівтар, зміна фази, смерть боса. Перевіряє тест
`SoundsThatBelongToThePlayerRatherThanToAPlaceAreNotPositioned`.

## 8. Дакінг

Гучні моменти **звільняють собі місце**, а не перекрикують. Зміна фази й смерть
боса притискають кімнату на 70 % і музику на 50 %; удар боса й парирування —
кімнату на 35 %; телеграф ривка — на 60 %.

Дакінг **ніколи не глушить у нуль** (стеля 0.15): шина в нулі — це баг, який
звучить як аварія. Повернення за 0.9 с.

## 9. Кімната

Дуже тихий безперервний шар плюс рідкісні деталі — камінь, ланцюг, крапля,
вітер — з **випадковим проміжком 7–21 с**. Рівний інтервал перестає бути
кімнатою й стає метрономом.

**У бою з босом деталі вимикаються**, а шар притискається: бою потрібне місце
більше, ніж атмосфері. Сам шар лишається — тиша звучала б як поломка.

Луп зшитий кросфейдом на півсекунди, тож на стику немає клацання.

## 10. Hit-stop і час

Звуки йдуть на **немасштабованому часі**, тож зупинка кадру не обриває звук
удару, який її й викликав. Одноразові звуки доживають природно й **не
перезапускаються** після розморозки.

## 11. Чистота

| Момент | Що робиться |
| --- | --- |
| смерть гравця | лупи стоп, кімната й музика притиснуті |
| відродження | `StopAll()` — жодного лупа з минулої спроби |
| скидання ворога | лупи стоп |
| бос до фази 1 | музика назад в Exploration |

Луп — це те, що найлегше забути зупинити, тому `LoopingVoices` рахується окремо
й перевіряється тестами.

## 12. Музика

Музики **немає**, і директор цього не приховує: без призначеного треку він
змінює стан, піднімає подію й грає тишу.

Стани: `Exploration`, `BossIntro`, `BossPhaseOne`, `BossPhaseTwo`,
`BossVictory`, `Death`. Усі переходи зрізу вже заведені й перевірені, тож
написати трек пізніше — це додати кліпи, а не протягувати нову систему крізь бій.

## 13. Імпорт

| Тип | Завантаження | Стиснення |
| --- | --- | --- |
| короткі (< 3 с) | DecompressOnLoad, preload | PCM |
| довгі (≥ 3 с) | Streaming | Vorbis 0.7 |

Усе моно: гра збоку, панорама рахується з позиції в світі.

## 14а. Багатші звуки, 2026-10-19 (гілка `cloud/audio`, чекає локальної перевірки)

Рішення Claude за постійною згодою. Звук і далі лише через `AudioManager.Play(AudioId…)`; нові `AudioId` —
у кінці переліку.

- **Нові рецепти синтезу** (`PlaceholderAudioArt`), кілька шарів кожен, і **кожен варіант бере свої
  параметри зі свого зерна**, тож вісім кроків — вісім різних кроків, а не один файл із джитером:

  | Рецепт | Шари | Звуки |
  | --- | --- | --- |
  | `Footfall` | гуп п'яти з падінням висоти, клац носка через 12–30 мс, пісок | крок героя (8 варіантів), приземлення (4) |
  | `Scuff` | смуга шуму, що падає, із тертям 28–60 Гц | старт і розворот бігу, відштовх від стіни |
  | `Slash` | повітря з раннім піком, розгортка вгору й спад, тонкий спів леза | замахи меча (6) і дворучника (4 + 4), важкий замах (4) |
  | `Impact` | транзієнт, гуп із падінням висоти, плоть, хрускіт, цок леза | влучання (6), важке влучання (4) |
  | `DashBurst` | видих на старті, розгортка, тріпотіння плаща 16–28 Гц | ривок на землі й у повітрі (по 4) |
  | `UiClick` | м'який дерев'яний цок із ледь чутним дзвоном | навігація (5) |
  | `UiUp` / `UiDown` | дві ноти через квінту, 45 мс між ними | підтвердження й відкриття / скасування й закриття |

  Броня (6) і крит (4) — старі рецепти, більше варіантів.
- **Без повторів удвох**: при 4+ варіантах не грає жоден з **двох** останніх (`AudioEvent.PickClip(ref,
  ref)`), тож немає й чергування А-Б-А-Б; при 2–3 — як раніше, не той самий двічі.
- **Нові звуки** (у кінці `AudioId`): `FootstepScuff` — пил старту й розвороту (`FeedbackKind.RunDust`),
  `WallJumpKick` — відштовх від стіни (`FeedbackKind.WallJump`). Рівний біг і далі без пилу й без
  зайвого звуку: кроки йдуть від кадрів бігу.
- **Інтерфейс нарешті звучить**: звуки UI були в бібліотеці, але меню їх не грали. Тепер їх грає
  `MenuInput`, через який читають клавіші всі екрани: крок фокусу — `UiNavigate`, підтвердження —
  `UiConfirm`, Esc і «назад» на геймпаді — `UiCancel`. Інтервал 0,06 с у підтвердження й скасування
  тримає одне натискання одним звуком, навіть коли кадр питають два екрани. `UiOpen` / `UiClose` для
  паузи — після злиття з `cloud/menus` (ті самі рядки `PauseMenu`).

## 15. Відомі обмеження

- **Увесь звук — процедурні плейсхолдери.** 224 кліпи, синтезовані кодом
  (шум, фільтри, сінуси, реверс). Кожна родина має свій рецепт, тож вогонь, лід,
  аркана й Тінь **справді різні на слух** — але це не звуковий дизайн.
- **Немає AudioMixer.** Шини реалізовані множенням гучності в менеджері, а не
  групами мікшера. Для зрізу достатньо, для сайдчейну й ефектів — ні.
- **Немає реверберації й зон** (пп. 148–150). Без мікшера немає й reverb zones.
- **Немає музики** — лише стани й переходи.
- **Немає озвучення** і воно не планувалося.
- **Кроки лише гравця.** Вороги мають звук кроку в бібліотеці, але анімації
  ворогів не піднімають покадрову подію, тож кроки зомбі й щитоносця **не
  підключені**. Потрібна та сама подія кадру, що є в гравця.
- **Немає окремих звуків матеріалу цілі** (п. 29): `HitArmor` існує, але вибір
  між плоттю й бронею за тегом цілі не реалізований — грає `HitFlesh`.
- **Ручного прослуховування не було.** Пункти 231–254 вимагають грати й слухати;
  перевірено лише те, що піддається автоматизації. Чи *приємні* ці звуки —
  невідомо; перевірено, що вони різні, обмежені й прибираються за собою.
