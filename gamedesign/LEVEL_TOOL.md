# Инструмент уровней (п. 1 списка «Мир из 15 зон», 2026-10-03)

Зона пишется текстом — `Assets/Game/Levels/<зона>.txt`, один файл на зону. Из него же собираются
геометрия, вещи и данные графа (области, связи, алтари), поэтому карта не расходится с уровнем.
Опора — карты пользователя (`reference/maps/`): комнаты, их соседство и иконки переносятся оттуда.

## Формат

```
zone zone_forgotten_tomb       # id зоны (как в графе)
cell 0.5                       # размер клетки в мировых единицах (по умолчанию 0,5)
origin -22 0                   # мировая точка левого нижнего угла клетки (0, 0)
abilities dash                 # что у игрока точно есть при входе: с этим проверяется основной путь

room room_tomb_entrance «Вхід до Гробниці» at 0 0   # id, имя, левый нижний угол в клетках зоны
flags secret optional boss=guardian-of-the-tomb needs=double-jump exit=E
key s start
key a altar tomb-altar-01 «Вівтар входу»
grid
##########
#........#
#.s..a....                     # открытый край — проход в соседнюю комнату
##########
end

link room_a room_b door | oneway | ability=id | boss=id | shortcut=id from=room_id | zone
```

- Строки сетки — сверху вниз, все одной ширины. `#` камень, `%` гладкий камень (не цепляется), `=` уступ
  или доска — **односторонний** (с 2026-10-25, просьба пользователя): держит сверху, снизу и сбоку
  пропускает — прыжок из-под уступа встаёт на него (`OneWayPlatform`; `LevelReach` считает так же), `^` шипы, `.` воздух, строчная буква — вещь из `key`.
- Комнаты — прямоугольники, не перекрываются. Открытая клетка на краю комнаты должна смотреть в открытую
  клетку соседней — это связь (`Normal`, направление по стороне). Проход в никуда или в стену соседа —
  ошибка; край в другую зону разрешает `exit=NSEW`.
- `link` — только когда связь больше, чем проём: дверь, ворота способности/босса, шорткат, односторонний
  спуск, граница зон. Связь без проёма (например, падение сквозь пол) тоже пишется `link`.
- Флаги: `secret` (найти можно только войдя: триггер по комнате без стен), `optional`, `boss=id`,
  `needs=ability` — ради какой способности комната построена.

| Вещь (`key`) | Аргументы | Что ставится |
| --- | --- | --- |
| `start` | — | точка проверки основного пути (в игру не попадает) |
| `altar` | id, имя | алтарь (`Checkpoint`), запись алтаря в графе |
| `gold` | сумма, постоянный id | кошель |
| `item` | id предмета, постоянный id | находка |
| `ring` | — | кольцо гака |
| `enemy` | имя префаба | враг |
| `shard` | `health`/`mana`, id | осколок сосуда (id в сохранении — `explore-<вид>-<id>`) |
| `reward` | id способности, имя | способность, лежащая в мире (`TraversalReward`) |
| `urn` | id, золото | урна / черепа / ящик по зоне комнаты (`BreakableProp`, 2026-10-19): разбивается одним ударом, золото — один раз за игру (`break-<id>`), стоит снова после отдыха. Буква — в клетке над полом шириной 3 клетки, 2 клетки воздуха сверху |
| `breakable` | id, высота в клетках | стена тайной комнаты, две клетки от буквы вправо (`BreakableWall`, вуаль над комнатой) |
| `spot` | имя | точка для собственного строителя зоны (босс, люди, камни, манекены); `SpotFeet(zone, имя)` |

Вещь стоит в своей клетке на её полу (буква — в первой клетке воздуха над полом).

## Проверка досяжности

`LevelReach` двигает героя настоящим `PlayerMovementLogic` (50 Гц) по клеткам: прыжки с места и с
разбега, сход с края, удержание и отпускание направления до и после вершины, короткий прыжок, второй
прыжок, рывок в воздухе, кольца гака (тянет в 7,5, отпускает в 1,9 под кольцом с подскоком 7). Тело —
коробка 0,8 × 1,6. Стены ничего не дают (бег по стене и прыжки от стен не считаются).

Две модели: **строгая** (прыжки ×0,97, бег ×0,95) — для основного пути и ловушек; **щедрая** (×1,04,
×1,05) — для вопроса «закрыты ли ворота». Настоящий герой между ними; опора — середина стоп (±0,25:
капсула круглая, с угла дальше она соскальзывает). `LevelReachTests` держит обе: что разрешает строгая,
герой делает; что сделал герой, щедрая разрешает (замер 2026-10-03: со вторым прыжком герой встал на 3,5; пропасть 5,0 не перепрыгнул).

`LevelCheck.Problems(zone)` — ошибки текста и:

- каждая основная комната достижима от `start` с `abilities` зоны;
- **нет ловушек**: с каждого достигнутого пола есть путь назад к старту — и с `abilities` зоны, и со
  способностью каждых ворот, и со всеми сразу (2026-11-06: «Глибоке коріння» пускало вниз на гаке и не выпускало).
  Со способностью ворот выходом считается и зажжённый алтарь (мандри, `FAST_TRAVEL.md`), и спуск сквозь дно с
  `exit=S` в соседнюю зону (`LevelReach.LeavesZone`). Нашлось и исправлено: ниши куполов Поховальної зали (свод
  над полкой с кошелем и урной упирался в голову — купол шире на 3 клетки), пол за шипами «Тернового шляху» (три
  уступа обратно вверх), корни-ступени «Глибокого коріння»;
- необязательная комната без `needs` достижима;
- комната с `needs=X` недостижима без X даже щедрой моделью («nearly reached» — добавить клетку) и
  достижима с X строгой.

Числа в клетках по 0,5: прыжок — 3 клетки вверх (4 — уже нет), второй прыжок — 6 (7 — на грани, ворота
только от 8), разбег — пропасть в 8 клеток (10 — на грани, 11 — нет), рост героя — 4 клетки воздуха.

Опыт Гробницы (п. 3): шахты — уступы по 4 клетки у стен, зазор 4, подъём 3, уступ той же стороны
на 6 выше (так строгая модель проходит и вверх, и вниз); над уступом, с которого прыгают, ничего ближе
6 клеток; граница двух комнат не проходит по строке уступа (иначе «проём смотрит в стену»).
Опыт Леса (п. 4): уступ в 1–3 клетках над полом — стена для ходьбы (перепрыгивать), под уступом
ходят, только если он на 5+ клеток выше; люк в полу шире 8 клеток не перепрыгнуть — над ним «камень»
для шага; дверь ворот способности не ставить в стену шахты, мимо которой падают (в неё влетают в
падении) — ворота делать подъёмом через люк или в стороне от падения; комната-шахта без единого пола
«не достигнута» — дать ей хоть сучок.
Опыт Столицы (п. 6а): ошибка ключа («key never placed») прячет проверку досяжности — сначала чистить ключи;
башня между ярусами — лестница уступов, а не мосты с люком (сквозь люк 2 юнита модель не пролезает); ярус
выходит на запад с левого уступа, на восток — с правого, на 1,5 выше; кольцо гака — прямо над уступом, иначе
линия цепляет край свода.
Черновик текста удобно генерировать скриптом и править руками; источник истины — `.txt`.

Скрипты проверки текста (`tools/level-drafts/`, без Unity): `draw_zone.py <зона>` — схема зоны (камень, уступы,
шипы, рамки комнат, враги красным, находки золотом); `empty_rooms.py <зона>` — большие комнаты без врагов и находок;
`floating_things.py <зона> [--fix]` — вещи в воздухе (вернуть полку); `untidy.py <зона> <коммит LevelTidy> [--fix]` —
уступы, которые `LevelTidy` убрал как тупики, хотя они вели к двери, находке или были испытанием;
`populate.py [--fix]` — что поставлено в пустые комнаты (2026-11-06); `relief.py <зона> <комнаты…>` — рельеф пола
плоской комнаты: пологие кочки до трёх клеток и лужи, свой seed на комнату (2026-11-07). После любой правки — `LevelCheck`.

**Архитектурный язык Гробницы** (2026-11-02, пользователь: «все паркуры и стены логичные и приятные»; решено Claude):
плита не висит посреди зала просто так. Подъём в зале — **опора** из свода (камень 2 клетки шириной) с **кронштейнами**
по очереди слева и справа, каждые 3 ряда; под опорой — 4 ряда прохода (рост героя). Так перестроены Вход, оба купола
Погребального зала, Восточная капелла, Восточный зал. В шахтах — уступы у стен «этажами», между ними плиты на цепях
(«Цепная шахта», «Нижние цепи», Затопленный склеп — цепи и есть тема). Висящий камень — плита на цепях или уходит
(Подход к Стражу, Обрушенный склеп). `LevelTidy` пробует то же сам («якоря»: балкон у стены, мостик до стены, колонна с
пола; путь между полами может удлиниться не больше чем на 2 хода) — в залах это редко удаётся, там правка руками
(`tools/level-drafts/room.py`) и `LevelCheck`.

**Архитектурный язык Леса** (2026-11-03, пользователь: «второй уровень так же»; решено Claude): лестница из висящих
уступов двумя столбцами — это **дерево**: стволу в щели 2 клетки между столбцами (позади героя, без коллайдера), каждая
ветка дорастает до ствола, внешний конец сдвинут на -1…+1, каждая четвёртая — длиннее (передышка). Текст правит
`tools/level-drafts/trees.py forest` (только воздух, потом `LevelCheck`), ствол painter находит сам (`terrain.js`,
`trunksOf`: два висящих уступа через щель 2 клетки) и рисует от земли до свода или, под небом, с кроной. Висящие уступы
зоны — `tools/level-drafts/floating.py <зона>`. Так стали деревьями Старое кладбище, Сломанная арка, Сторожевая вежа,
Кладка над яром, Нижняя галерея, Грибная заводь.

**Уборка паркура** (`LevelTidy`, 2026-10-27, просьба пользователя «удобнее и логичнее»; правила решены Claude):
`ForgottenKingdom.EditorTools.LevelTidy.Start("<зона>")` в живом Editor — минуты в фоне, журнал
`Artifacts/LevelTidy/<зона>.log`, текст зоны переписывается сам; потом `render.js`, `place.py`, `Scene<Зона>.Apply`,
`SceneReactive.Apply`. Меняет только `=`. Первым проходом — «первая ступень» (2026-10-28, «не могу запрыгнуть на
первый блок»): уступ, на который удобная модель не попадает ни с чего ниже (только падением сверху), опускается
на 1–3 ряда или получает ступень на 2–3 ряда ниже у своего края. Дальше: уступ в 1–3 клетках от стены прирастает к ней, две части одного ряда
через щель ≤ 2 сливаются, уже 4 клеток — расширяется, тупик уходит. Правка остаётся, только если `LevelCheck`
чист, каждый достигнутый пол (камень) и каждая вещь достигаются как раньше (вещь — с того же ряда), ни один путь
между двумя полами не стал длиннее ни на ход (строгая модель) и удобная модель (прыжок и бег ×0,95 от строгой)
не потеряла ни одного пола. Без последнего правила уходили целые подъёмы: зона — одно кольцо, «дальним путём»
досягаемо всё.

**Где прыжок на грани** (2026-11-10): `-executeMethod ForgottenKingdom.EditorTools.LevelTidy.ComfortReport` (batchmode,
~1 мин) пишет `Artifacts/LevelComfort.txt` — `LevelCheck` каждой зоны и полы/уступы, которые берёт строгая модель, но не
удобная (со способностями зоны и со всеми воротами). Пусто — паркур зоны удобен.

## Сборка и просмотр

- `ContentBuilder.BuildLayout(zone, parent, block, context)` — блоки (их вид даёт зона через `block`),
  шипы, вещи, триггеры тайных комнат; `LayoutGraphJson(zone)` — области, связи, алтари для графа.
  `LevelSolids.BuildColliders` — только коллайдеры (для тестов).
- `Forgotten Kingdom/Levels/Check and Draw Layouts` (`LevelTools.RenderPreviews`) — проверяет все
  `Levels/*.txt`, пишет проблемы в лог и рисует `Artifacts/LevelPreviews/<файл>.png`: камень, уступы,
  шипы, вещи, зелёным — полы, достижимые от старта.

Тесты: `LevelLayoutTests` (EditMode, 6), `LevelReachTests` (PlayMode, 2: полки 1,5–4,0, пропасти 4–5,5).

## Нарисованный уровень (painter, 2026-10-04; пилот — Гробница)

Вид зоны рисует код по её тексту — `design/levels/painter` (погоджений макет — `design/levels/tomb-look`).
Блоки остаются только коллайдерами; всё видимое — картинки:

- **камень площадки** — куски 16 × 16 юнитов, 48 px/юнит (`Art/Levels/<Зона>/Terrain/t_<x>_<y>.png`, угол —
  `(x·16, y·16)`): мягкое поле из клеток, размытое и сдвинутое шумом (органические стены и потолки), а у
  верха, где стоят, — ровно по клетке (картинка не врёт о коллайдере); тёмная сердцевина, кладка у края,
  холодный отблеск на гранях к свету, светлый кант с пылью на полах и уступах, цепи у висящих уступов;
- **стена тайника** — отдельный кусок поверх проёма (`Breakables/b_<клетка>.png`): в камне площадки там
  воздух, разбитая стена оставляет дыру;
- **фон комнаты** — два слоя (`Rooms/<id>_mid|near.png`, 32 px/юнит): `mid` — неф в тумане и аркада
  (больше комнаты на 3 юнита, сдвигается `RoomParallax` в маске комнаты), `near` — стена с прозрачными
  арками, статуи, знамёна, лучи, пыль; пещеры (`looks.js`, `caves`) — глыбы, корни, грибы; тайники —
  ниши с черепами. У каждой комнаты свой seed — картинки не повторяются.
- **передний план** (`Rooms/<id>_front.png`, `design/levels/painter/front.js`, 2026-10-27, просьба пользователя: «вайб и
  атмосфера как в Hollow Knight, не копировать»): тёмные силуэты, свисающие со сводов — лианы с острыми листьями,
  цепи, корни, сталактиты (набор по характеру комнаты) — и мягкие пятна-боке; шире комнаты на 2 юнита, слой
  `Foreground`, `RoomParallax` с коэффициентом −0,2 (едет навстречу камере). Длина не больше четверти комнаты и 4 юнитов,
  и прядь кончается не ниже 2,4 над ближайшей поверхностью под ней (2026-10-28: в Восточном зале густые пряди слились в
  чёрное пятно и, сдвинутые параллаксом, прятали героя); боке мелкие и тусклые. Гробница и Лес (`jobs.js`, `FRONT_ZONES`;
  Лес — 2026-11-04, решено Claude): в Лесу свисает только живое (лианы, корни; в подземных — корни и капли), а в
  комнатах под небом верхний камень лишь граница — оттуда ничего не свисает, вместо этого из-за кадра в углы входят
  две-три тяжёлые ветви с листвой, не ниже 2,4 + 1 над самой высокой поверхностью под ними.
- **детали в толще камня** (2026-11-04, «чтобы игра выглядела дорого»; решено Claude, `terrain.js`, `drawInside`): в
  полосе 1–3,5 юнита от края камня (видна из комнаты, но не там, где стоят) — в Гробнице замурованные черепа, кости и
  трещины, в Лесу корни сквозь землю и камешки; только поверх камня, бледно.
- **настоящий свет нарисованных огней** (2026-11-04, решено Claude): painter отдаёт, где нарисовал свечи и светящиеся
  грибы (`index.html?what=lights`, `node tools/level-art/lights.js <зона>` → `Art/Levels/<Зона>/lights.json`, после
  `render.js`), `SceneLevelLights.Apply` ставит на каждый Light2D — тёплый на свечу, холодный на гриб — только на слой
  `Characters`: проходящий мимо свечи герой теплеет с её стороны, картина остаётся как написана.
- **гамма комнаты и реквизит** (2026-10-28, пользователь: «кардинально иначе, красивее, менее сыро»; решено Claude):
  камень был серо-синей наклейкой на живописных фонах. `python tools/midjourney/palettes.py <зона>` берёт из фона
  Midjourney каждой комнаты тень, тон и свет (`painter/palette-<зона>.js`); с `roomPalette` в `looks.js` масса —
  тёмный силуэт в тонах своей комнаты, грани к свету — её светом, кант и реквизит — её цветами, между комнатами
  плавно (размытая сетка цветов по клеткам). `props.js`: по верху полов мох, обломки, кости и черепа, свечи с
  тёплым ореолом — низко, густо по шуму, не у обрыва. Пока Гробница.
- **материалы** (2026-10-28, пользователь: «текстуры дешёвые; не везде камень — мосты, дерево»; решено Claude):
  фото-текстуры Midjourney на камне сняты (`looks.js` без `textures`; код `textures` и `textures.py` остались).
  Масса — `mass`: `blocks` (Гробница, Столица — крупная кладка, шов тонкой тенью) или `rock` (Лес, Село — пятна и
  пологие пласты); верх поверхности — `cap`: `flagstones` (плиты), `grass` (трава, `look.grass`), `trim` (тёсаный
  карниз с зубцами). Уступы `=` — `materials.js` по месту: у стены полка с подкосом / ветка (Лес) / балкон на
  консоли (Столица); свободный от 8 клеток — мост из досок с поперечинами и подвесами (цепь, верёвка, корень);
  короче — подвешенный настил, бревно (Лес) или каменная плита (Гробница, Столица), выбор по seed уступа.
- **рисованный декор** (2026-11-11, решено Claude по постоянному согласию): 12 предметов Nano Banana
  (`design/levels/midjourney/tomb/props`, `MIDJOURNEY.md` §3) — статуи, саркофаг, канделябр, обломок колонны,
  алтарь-корона, урны, кости; знамя, цепи, корни со сводов; паутина в верхних углах. `python tools/midjourney/dress.py
  tomb` вырезает их с magenta, делает на ступень темнее и тусклее игрового поля и кладёт на `near` комнаты: стоящие —
  на каменный пол текста (`#`, не уступ `=`) в чистом воздухе (не на дверь, врага, находку, шипы), висящие — со свода
  не ниже 2,4 юнита над полом под ними. У комнаты свой seed и свой набор из 3–4 видов (арена — статуи и знамёна,
  тайник — урны и кости, пещера — обломки и корни), наборы двух комнат не совпадают; узкие комнаты без пола
  (Реліквіарій — шипы) остаются пустыми. `near` сначала заново рамка `place.py`, повтор безопасен. Порядок:
  `render.js` → `place.py` → `dress.py` → `RefreshLevelArt`. **Лес** (тот же день, `dress.py forest`): пень, надгробие,
  руина арки аббатства, придорожная каплица охотников, ядовитые грибы, упавшее бревно, колесо телеги, терновник,
  череп оленя на колу; плющ и мох, корни, паутина с росой. Классы комнат — из `looks.js` (`enclosed`, `underground`,
  `poison`): под открытым небом верхний камень — лишь граница, ничего не висит; под землёй — корни, грибы, паутина.
  **Село** (`dress.py village`): бочки с ящиком, телега, колодец, плетень, упавший колокол, пугало с вороной,
  придорожный крест со свечой, жаровня, горшки; фонарь на верёвке и пучки трав; паутина в саже. Классы — `open`
  (улицы под небом: ничего не висит) и `stone` (церковь, крипта, погреба) из `looks.js`, остальное — избы. Паутина
  во всех зонах серая: сквозь пряди просвечивал magenta.

**Лес** (2026-10-19, макет `design/levels/forest-look`): тот же камень с мхом на канте и корнями вместо
цепей у висящих уступов (`looks.js`, `forest`); тло — `forest-backdrop.js`: открытые комнаты — небо, луна
не в каждой, ряды мёртвых дубов в тумане, местами руина аббатства; закрытые (`enclosed`, как
`ForestEnclosedRooms`) — чаща; под землёй (ниже `groundLine`) и тайники — корни, грибы, ядовитый свет.
Закрашенный Лес не строит тайлы, убранство комнат, землю и общий параллакс; `SceneForestLook` оставляет
только лунный свет.

**Село** (2026-10-19, макет `design/levels/village-look`): тло — `village-backdrop.js`: улицы (`open`) —
сумерки с жаром над Столицей, ряды хат с огоньком в окне, колокольня, дым; церковь — неф и разбитый
витраж со свечами; каменные (`stone`) — своды и бочки; остальные — бревенчатые стены и балки. Закрашенное
Село не строит тайлы и тайловое тло комнат; реквизит и его тёплый свет (фонари, кузня) остаются.

**Столица** (2026-10-19, макет `design/levels/capital-look`): тло — `capital-backdrop.js`: открытые ярусы — пепельно-
красное небо, шпили палаца, аркады; храм и крипты — каменные нефы; цистерна — вода и водопад; башня — шахта; арены
Командора и Короля — тронные залы. Закрашенная Столица не строит тайлы и общий параллакс; реквизит, жаровни и
печати со светом остаются.

**Mac без Chrome и без открытого Editor** (2026-11-10): снимки делает `tools/_shared/browser.js` — один headless-браузер
на весь прогон по протоколу DevTools, Chrome или Brave (Brave на `--screenshot` зависает). `render.js <зона> 4
<начала имён через запятую>` рисует только названные файлы (`t_-2_2.,room_tomb_column_front,b_`) — куски камня под
изменёнными комнатами, без шума в остальных. Python-инструменты — `.venv/bin/python` (Pillow, numpy; папка вне git).
Сцена без живого Editor: `Unity -batchmode -quit -executeMethod ForgottenKingdom.EditorTools.ScenePasses.ApplyZone
-zone <зона>` (импорт арта, `Scene<Зона>.Apply`, `SceneReactive`, `SceneStones`, `SceneLevelLights`; ~3 мин). Проходы
переписывают fileID во всех сценах — чужие зоны и `MainMenu` откатить `git checkout`, как и `ProjectSettings/*`,
которые Unity переформатировал.

Порядок: правка текста → `node tools/level-art/render.js <зона>` (headless-браузер, ~1 мин) →
`ContentBuilder.Build` → `ContentBuilder.RefreshLevelArt` (импорт) → `Scene<Зона>.Apply`. Просмотр без Unity:
`node design/ui/_shared/serve.js` → `/design/levels/painter/index.html?zone=tomb&what=preview&ppu=12`
(вся зона) или `&what=view&x=<левый край>&y=<низ>&ppu=60` (кадр камеры 32 × 18 юнитов). Зона без папки арта
остаётся на тайлах. `render.js` (Node, macOS и Windows, 2026-10-25 вместо zsh-скрипта) сам поднимает сервер, браузер —
`CHROME=<путь>` или обычное место установки Chrome; стирает каждый файл перед снимком: прерванный прогон оставляет
зону без арта — перезапустить целиком. Chrome на Windows рисует тло чуть иначе, чем на Mac: картинки комнат, текст
которых не менялся, вернуть `git checkout`, чтобы в коммите был только нужный арт. Комнаты с фоном Midjourney — после
рендера `python tools/midjourney/place.py <зона>`. Правка одной комнаты — `tools/level-drafts/room.py` (печатает
сетку с номерами, заменяет её, не трогая края-проёмы). `map-art` пока на `tools/_shared/shot.sh` (zsh).

Формы в тексте (генератор Гробницы): своды (`vault`), неровные потолки пещер (`rough_ceiling`), наплывы
стен (`bulge`), бугры осыпи (`hump`) — только там, где не мешают проходу; проверка — `LevelCheck`.
